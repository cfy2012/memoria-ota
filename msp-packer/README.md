# Memoria MSP 打包器

Memoria OS 应用上架工具箱（图形界面）。把你自己写的 BASIC 程序打成 `.msp` 安装包、生成商店清单，走**审核制上架**。纯 Python 标准库（tkinter + email），零第三方依赖，双击 `msp-packer.exe` 即用。

---

## 一、先用一个故事搞懂三个页签

假设你写了个 BASIC 小游戏 `猜数字.bas`，想让商店里能下载到它。全程四步：

```
第 1 步 打包     → 【应用包页签】选 app.bas、填名字和版本号
                   → 桌面出现 猜数字-1.0.0.msp
                   → 同时自动弹出一封审核邮件（收件人已填好）
第 2 步 审核     → 你核对邮件里的校验码 + 把包放掌机试玩
                   → 通过 → 在邮件客户端里点"发送"（留档）
第 3 步 上架     → 【store 清单页签】把 .msp 加进清单生成 manifest.json
                   → manifest.json + .msp 一起丢到服务器
第 4 步 下载     → 掌机商店刷列表 → 下载安装 → 桌面出图标
```

三个页签各管一步：**应用包 = 第 1 步**，**store 清单 = 第 3 步**，**音频包 = 给声音素材单独打包用的（见下）**。

## 二、页签详解

### 页签 1：应用包（BASIC 程序 → .msp）★ 主力

| 输入项 | 填什么 | 举例 |
|---|---|---|
| 应用名 | 小写字母/数字/连字符 | `guess-number` |
| 版本号 | 三段 x.y.z（**更新判断就靠它**） | `1.0.0` |
| 入口脚本 | 你的 BASIC 程序（.bas） | `猜数字.bas` |
| 附加文件 | 程序要用的数据/资源（可选） | 关卡.txt、字体.bin |
| 图标字符/颜色 | 桌面图标样子（可选） | `✦` / `#4fc1ff` |

点「**打包到桌面**」后发生三件事：

1. 桌面出现 `guess-number-1.0.0.msp`——这就是给掌机装的"应用安装包"
2. 桌面出现 `guess-number-1.0.0-审核.eml` 并自动打开——**审核邮件**，收件人、校验码（CRC32/SHA256）、附件全部预填好，你核对完点发送即可
3. 商店以后判断"要不要更新"就看版本号：掌机装过 1.0.0，商店出现 1.1.0 → 标"可更新"

**.msp 里面是什么**：一个带 CRC 校验的多文件容器——`manifest.json`（名字/版本/入口）+ `app.bas`（你的程序）+ 附加文件。BASIC 语法零改动，.msp 只是"应用外壳"。

### 页签 2：音频包（media .msp）

**这是干哈的**：给**声音素材**单独打的包——比如你的游戏要 5 个音效（开炮.wav、捡金币.wav…），把这堆 wav 打成一个 `.msp`，掌机下载后自动解包存进 `/audio/` 目录，游戏里 `play` 语句就能放。

它和应用包的区别：

| | 应用包 | 音频包 |
|---|---|---|
| 内容 | app.bas 程序 + 数据 | 纯音频（.wav/.mp3/.m4a） |
| 装到哪 | /scripts/ + 桌面图标 | /audio/ |
| 桌面图标 | 有 | 无（不是程序，是素材） |
| 包内格式 | MBND 多文件节表 | 单文件 MSPACK |

**什么时候用**：你的应用需要自带音效就打一个音频包，和应用包分开上架。不需要音效就不用管这个页签。

### 页签 3：store 清单（manifest.json）

**这是干哈的**：商店的"货架清单"。掌机的 store 应用打开时，先下载这个 `manifest.json`，才知道货架上有什么、每个包多大、去哪下载、CRC 是多少（防下坏）。

三个输入项：

- **源地址 base_url**：你放包文件的服务器地址，比如 `http://example.com/pkg`
- **文件列表**：点「添加」把打好的 .msp 都放进来
- **清单输出**：生成的 manifest.json 存哪（默认就存当前目录）

生成后把 **manifest.json 和所有 .msp 一起**传到服务器同一个目录，掌机 TF 卡 `/mem_fat/store_url.txt` 写一行 manifest 的网址，商店就能刷出来了。

## 三、审核上架流程（自动 → 人工）

2026-10-07 拍板：**打包不自动上架，必须人工审核**。

1. 打包完成 → 自动生成审核邮件（收件人 `cfy_20120331@outlook.com`）并打开
2. 邮件正文带三件套：**包大小 + CRC32 + SHA256**，附件是 .msp 本体
3. 审核方法（邮件里也写了）：
   - 用打包器重新打同名包，比对校验码一致 → 包没被篡改
   - 或把 .msp 放 TF 卡 `/scripts/` 实测运行
4. 通过 → 在邮件客户端点发送（留档确认）→ 用「store 清单」页签上架
5. 不通过 → 不发送，回打包器改完重打（新版本号）

## 四、命令行用法

```
msp-packer.exe                       # 图形界面
msp_packer.py --selftest             # 无界面自测（5 项：音频包/版本号/应用包/清单/审核邮件）
D:\py\python.exe msp_packer.py       # 源码跑 GUI
```

## 五、.msp 头格式（MSPACK，对齐固件 package_format.cpp）

`#pragma pack(1)` 共 50 字节头 + payload：

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0 | magic | char[6] | 固定 `MSPACK` |
| 6 | version | uint32 LE | 版本号：应用包 = x*10000+y*100+z（1.2.0→10200） |
| 10 | name | char[32] | 包名，NUL 结尾（白名单 `A-Za-z0-9_.-`） |
| 42 | payload_size | uint32 LE | payload 字节数（上限 1MB） |
| 46 | crc32 | uint32 LE | payload 的 CRC32（zlib 标准，与固件 crc32_compute 逐位一致） |

应用包 payload 以 `MBND` 开头（多文件节表，规范见 msp_packer.py 文件头注释），音频包 payload 就是音频文件本体。

## 六、部署到掌机

1. manifest.json + 包文件传到任意 HTTP 服务器（或 GitHub 仓库）
2. 掌机 TF 卡 `/mem_fat/store_url.txt` 写一行 manifest 地址——默认源指向 raw.githubusercontent.com，**国内需重定向到你能直连的源**
3. 掌机连 WiFi → store 应用 → 刷新列表 → 安装 → 桌面出图标
